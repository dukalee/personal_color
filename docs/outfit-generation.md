# 의상 합성 이미지 (2개)

사용자 얼굴 + 진단된 계절의 팔레트(`best`)를 반영한 전신 이미지를 2개 생성한다 (로딩 시간 최소화).

## 조건

- 전신 사진 형태, 정면을 바라보는 자세
- **사용자의 얼굴 특징 유지** (과도한 변형 금지, 마네킹 금지)
- 의상 색상은 진단 유형의 `best` 컬러에서 선택
- **반드시 전신**: 머리 끝부터 신발까지 프레임 안에 완전히 보여야 하며 무릎·발목에서 잘리지 않는다 (화면에서도 `object-fit: contain`)
- 각 룩마다 상의·하의·신발·액세서리를 정하고, 같은 구성에서 이미지 프롬프트와 화면 설명을 함께 만든다 (`src/lib/openai/outfits.ts`)
- 설명은 잡지 에디토리얼 톤의 한국어 문장 (색상 이름 포함)
- 액세서리 금속 톤: 웜톤 골드 / 쿨톤 실버
- 2개는 **서로 다른 스타일**, 배경은 깔끔한 스튜디오
- 피할 것: 과도한 포즈, 과한 액세서리, 왜곡된 신체 비율
- 체형·외모에 대한 평가 표현 금지

## 성별별 스타일 구성

사용자가 사진 업로드 단계에서 성별(여성/남성)을 직접 선택한다. 선택값은 진단 프롬프트(참고 정보)와 의상 구성·이미지 프롬프트에 전달된다.

| # | 여성 | 남성 |
|---|---|---|
| 1 | 데일리 티셔츠 룩 | 데일리 티셔츠 룩 |
| 2 | 우아 원피스 룩 | 클래식 자켓 룩 |

- **남성에게는 원피스·스커트·힐/펌프스/플랫·이어링·숄더백 등 여성용 아이템을 절대 추천하지 않는다.** 이미지 프롬프트에도 "menswear only"를 명시하며, `outfits.test.ts`가 이를 검증한다.
- 남성 액세서리: 시계, 가죽 벨트, 얇은 체인 목걸이 / 신발: 스니커즈, 로퍼, 더비 슈즈

## 화면 표시

- 2개가 모두 생성된 뒤에만 결과 슬라이드를 보여준다 (생성 중에는 진행률만 표시)
- 슬라이드 4~5페이지에 룩 1개씩: 이미지 + 상의/하의/신발/액세서리 설명 (`docs/report-layout.md`)
- 생성에 실패한 룩은 슬라이드에 "생성 실패"와 사유를 표시한다 (재생성 버튼은 없으며, 처음부터 다시 진단해 재시도)

## 생성 검증과 실패 방지 (`generateOutfit`)

이미지 생성은 **실패로 끝나지 않도록** 단계적으로 시도한다 (최대 4회). 매 시도마다 `gpt-4o-mini`로 검사한다.

1. 일반 편집 → 전신·얼굴 유사도 검사를 통과하면 즉시 반환
2. 통과 못 하면 "더 멀리서 찍기" 지시를 더해 재시도
3. 3회차부터는 원본 사진을 **세로 2:3 캔버스 위쪽에 얹어** 몸이 들어갈 자리를 만든 입력으로 재시도 (`src/lib/padPhoto.ts`)
4. 일시적 API 오류(429·5xx·네트워크)는 지수 백오프로 최대 4회 재시도 (`withRetry`). 검사 호출이 실패해도 생성은 실패시키지 않는다(판정 불가로 처리)
5. 끝까지 기준을 못 맞추면 후보 중 **전신 우선, 그다음 얼굴 유사도가 높은 이미지**를 반환 (이 경우에도 화면에서는 `object-fit: contain`)

- **전신 검사**: 머리 끝과 양발·신발이 프레임 안에 모두 있는지
- **얼굴 유사도 검사**: 원본과 얼굴 특징(윤곽·눈·코·입·피부톤·헤어) 비교, 5점 만점에 4점 이상 통과. 판정이 거부되면 건너뜀
- 인증 오류(401/403)는 재시도해도 소용없으므로 즉시 오류로 알린다. 이때만 "생성 실패"가 표시된다.

## 프롬프트

룩별 프롬프트는 `src/lib/openai/outfits.ts`의 `buildOutfitPlan`이 상의/하의/신발/액세서리 구성에서 생성한다. 전신 노출(머리~신발, 잘림 금지) 문장을 항상 포함한다.
